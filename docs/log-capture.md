# 日志采集

[返回总入口](../README.md)

每个已连接到最终目标的普通终端，在 Xshell「工具 → 脚本 → 运行」执行一次工作台生成或导出的 JS。运行 Xshell 的 Windows 机器需要 .NET Framework 4.8；远程机器不需要安装 Bridge、审批桌面或全局技能。脚本内嵌便携 helper，校验 SHA-256 和长度后在当前用户 LocalAppData 下私有提取；helper 无网络监听、SSH、终端 API 或命令执行能力，仅通过标准管道读取本任务日志。

工作台“本机 Xshell”及“远程 Xshell”来源均可保存日志编码，默认 **自动**：按 BOM 识别 UTF-8、UTF-16LE 或 UTF-16BE；无 BOM 时严格按 UTF-8 处理。不用为编码修改 Xshell 配置。无 BOM 的 UTF-16、GBK（CP936）和 GB18030 必须在对应来源中显式选择一次，重新生成或导出并运行单文件脚本；无法可靠猜测无 BOM 的 GBK。显式选择与 BOM 冲突、非法字节或截断均失败，不替换为 U+FFFD。终端的 IsUtf8 不代表日志编码。日志必须是可打印文本；RTF、时间戳、ANSI/终端控制序列不支持；文件路径询问需要关闭。

任务前若用户日志已在运行，拒绝发送命令且不停止用户日志。每任务 helper 创建唯一私有目录，DACL 只授予当前用户和 SYSTEM 并继承给文件；持有并核对目录及祖先，预期的 `capture.log` 此时不存在。检查目标身份、目录租约及文件不存在后调用一次 StartLog；只有实际路径精确匹配且 Logging 精确为 true，helper 才打开这个固定路径并绑定文件身份。绑定检查目录身份、重解析点、单硬链接、最终路径、稳定文件 ID、可读性及大小；读句柄仅共享 ReadWrite，不共享 Delete。绑定和读取通过后才发送已批准命令。不采用编号路径或屏幕抓取。

正式捕获不读取 Screen.Get、Rows、Columns 或 CurrentRow。官方 Synchronous 和 WaitForStrings 只匹配拆分构造的 DONE 哨兵。DONE 在完整 END 行后打印，匹配后停止自己的日志，再通过持有句柄排空。编码在 helper 里增量严格转换为 UTF-8，停止日志后的最终 EOF 才刷新解码器；只有完整字符、完整 END 和退出码经最终校验后才完成。每次返回最多 16 KiB，原始日志和转换后输出各上限 8 MiB；管道请求最多 1 KiB、响应最多 24 KiB，严格序号。helper 空闲 15 秒或生命周期 2 小时自动退出。不得将任务命令交给 helper 执行。

输出是合并的终端转录文本，不是独立的原始 stdout/stderr。Bridge 仍按原有 1 MiB 输出保留上限标记截断；8 MiB 是本地捕获日志和转换后文本的各自上限。不会恢复被终端或日志配置改变的字节。打印内容必须是可打印文本；屏幕颜色、光标控制和交互程序不在支持范围。Xshell 可能直到 StopLog 才刷新，期间任务状态/心跳继续更新；没有实时输出不代表命令未执行。任务中不要手动输入或切换目标。

完成事件收到确认后才清理本任务文件和空目录、退出本任务 helper，停止自有日志后，如果路径仍为本任务路径且 Logging 精确为 false，给下一次日志设置此前观察到的基线路径；getter 不反映原先配置的下一路径，因此不声称恢复原配置。连续任务沿用基线，不把已删除的上次任务日志设为下一路径。完成传输不明时保留日志且不重试；完成确认后的清理错误会停止脚本并显示诊断路径，不改写已确认的任务结果。失败时保留任务目录；预期文件可能尚不存在，也可能出现未绑定的编号文件。读取达到 8 MiB 即失败并尽力停自己的日志，但外部写入器本身不受读取上限约束。异常结束和写入器不退出可能留下更多字节。未设置自动按天清理或删除其他任务文件；核查原任务、停止对应脚本/日志后，由操作员手动删除明确的 job 目录。提取目录以 helper 哈希和随机值隔离；正常脚本关闭时删除，崩溃残留也按明确目录人工清理。日志可能包含敏感终端输出。

同一 Windows 账户视为受信任操作员。句柄、文件 ID、共享和路径检查防止意外替换、误读外来日志、截断和越界读取；不构造对抗拥有同用户任意代码/内存写权限的安全边界。启动前存在的目标、硬链接及重解析点被拒绝；无法证明在“不存在”检查后创建普通文件的进程身份。来源身份改变或传输不明时，不发送待发内容到新身份、不重试事件或命令。unknown 后 agent 停止，Bridge 阻断后续队列。

本地 Node、32/64 位 cscript、实际 winexe 管道和原生假写入器验证不等于真实 Xshell 命令采集。用户运行 0.8.0 失败后，只读探针显示 Logging=true，实际路径在同一私有任务目录下为 `capture(2).log`，而预期为 `capture.log`；此前不存在目标文件的诊断成功。这支持此前预创建文件触发 Xshell 避免覆盖而选编号名的根因。新流程的真实 Xshell 文件共享、编码、实际命令捕获与最终刷新仍需在授权的非生产终端验收。

## 路径行为和可选诊断

[官方 Session API](https://netsarang.atlassian.net/wiki/spaces/ENSUP/pages/2237305704/xsh.Session) 描述路径设置与 StartLog；[官方脚本示例](https://netsarang.atlassian.net/wiki/spaces/ENSUP/pages/2237305760/Script+Example) 使用属性赋值后 StartLog。实测只支持将 getter 理解为最后打开的路径，并不能从中取得原先“下一次日志”配置。基线策略使用最初观察到的最后日志路径（可能为空）供后续日志使用；若用户实际配置的下一路径不同，脚本无法读回并恢复它。不要同时手动改动日志设置。

发送前允许 setter 后读回预期路径或原先读回值；其他值、异常或非字符串均拒绝。再次检查终端身份、目录租约、目标不存在及 Logging=false，StartLog 后必须核对实际路径、Logging=true、绑定文件身份及读取，才发送。路径或状态不匹配时不停止未验证的日志，提示人工核查；StartLog 部分失败仅在来源、路径、Logging 和文件身份均验证后停止。错误记录 NoSend 或 SendAttempted 及有界转义的实际/预期路径和 Logging 类型值；SendAttempted 包括 Send 部分抛错，结果不明。

可选 `agent/log_path_diagnostic.js` 是独立手动只读回测试，不调用 StartLog、StopLog、Send、进程或网络；正常单文件脚本不依赖它。它不能验证 StartLog 读回时机，也无法证明原始下一路径配置得到恢复。用户应核查会话日志设置；不要把此诊断当作实际命令捕获验收。
