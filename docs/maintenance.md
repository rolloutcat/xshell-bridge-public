# 维护与排障

[返回总入口](../README.md)

首次接入和日常操作见[使用指南](user-guide.md)。本页集中说明更新、终端清理及故障处理。

## 程序更新

“检查 GitHub”读取程序内置仓库的最新正式 Release 并比较版本；草稿或尚未发布时显示“无法获取发布”，不表示已经是最新版本。“获取最新源码”克隆该仓库的 `main`，仅获取文件，不构建或运行。当前版本不内置 ZIP 下载器：用户通过浏览器下载 lite 包及同名 `.sha256` 文件，再在工作台填写本地 ZIP 路径和预期哈希进行验证导入。

使用 lite 前确认工作台所在机器已有 WebView2 Runtime；离线且缺少运行时时，由用户安装微软提供的对应架构离线运行时。仓库地址编译在程序中，旧程序不会因为 Git remote 修改而自动改用新地址；切换到公开仓库需先使用已包含新地址的程序包。

`VERSION` 是 Go 与桌面的版本来源。工作台可检查更新、获取源码或导入用户提供的 ZIP。导入要求本地绝对路径和独立可信来源的 SHA256，校验包结构并解压到新目录，不自动运行包或覆盖旧文件。

应用前预览并确认。用户须先检查任务、停止和撤销接入并断开桌面拥有的 SSH 隧道。Bridge 使用原子停机屏障，候选内容和上下文变化会使确认失效。交接等待旧进程和 Bridge 锁退出，不强杀、不删除锁、不重放。新工作台沿用原宿主机 runtime；失败须人工核查。MCP/Skill 更新独立确认，未知配置不会自动覆盖。

## 接入脚本更新

本机脚本在“本机 Xshell”检查状态，预览并确认更新。清单校验归属、脚本内容和设置，版本与内容共同判断是否需要更新。手动修改、清单损坏或缺失、归属不明时拒绝覆盖，需人工检查；主 agent 凭据轮换后旧清单无法认证，也须人工处理旧受管文件。

远程脚本在“远程 Xshell”重新预览导出并私密传递。导出不覆盖已有文件；选择新的文件路径并核对最终版本。两种方式更新后都必须在每个终端手动重新运行，核对新接入代次并激活，不热替换正在运行的脚本，不重放命令。

断开或删除远程配置不会撤销已导出的来源凭据。需要撤销时，按受控流程轮换宿主机 agent 主凭据并重新生成或导出所有受影响脚本。关闭桌面会停止其所属 Bridge 和 SSH 进程；远端命令仍可能运行。切换目标或网络前先停止旧接入和隧道，再核实目标。

## 清理终端记录

在“会话与目标”每行点击“移除终端记录”，核对名称、分组、状态、完整会话 ID、接入代次及指纹，再确认一次。活动或待激活接入的确认明确写明“停止 Bridge 接入并移除”；这不会关闭 Xshell 标签或 SSH，也不会向终端发送命令。

“批量清理离线终端”只预览已经处于 detached（已撤销）、blocked（已阻止）、expired（已过期）的记录；不会仅凭旧心跳停止 active/pending 接入。预览列出全部候选和数量，最多 100 个；超过限制须先逐个移除部分记录。无候选时提示，无需确认。如果候选仍有未结束任务，整批拒绝，须先处理这些任务。

任一 pending、queued、dispatched、running 任务都阻止移除，包括已失效接入所关联的任务。unknown、completed、denied、cancelled 历史保留。移除是持久化逻辑归档，不减少状态文件或输出占用；任务记录仍可显示原终端身份、名称分组和输出。不提供物理删除或恢复旧接入的操作。

界面在离线、只读、编辑表单期间或工作台快照超过 10 秒未更新时禁用操作；已经显示的预览若观察到目标或任务变化立即失效。服务端检查始终为准。关闭对话框会取消票据；无需额外勾选框。

保存未改动的名称也会关闭弹窗；保存或关闭弹窗及成功刷新后，清理按钮按当前资格恢复。界面明确显示只读、离线、快照过期、编辑中或忙任务的原因及处理办法；候选中存在忙任务时禁用整批清理，不跳过该记录。`unknown` 不属于忙任务。

编辑名称依赖 `session_labels`，清理独立依赖健康握手中的布尔 `session_removal=true`，不依据版本号猜测能力。缺失、不正确类型或关闭的能力均禁用清理，并显示实际 Bridge / 工作台版本（缺失时显示未知）及维护窗口升级指引。仅重开桌面不会替换正在运行的 Bridge；本功能不自动重启或升级。

确认结果未知时只刷新列表或查询原任务，不自动重试。后来出现的离线记录须另行预览。

归档标记在 Bridge 重启后保留。默认工作台及 CLI/MCP 会话发现不返回已移除记录；旧脚本的 poll、heartbeat、event、激活和旧 instance 注册不能恢复它。用户以后手动运行接入脚本可创建全新 ID 和代次，名称分组沿用已有标签。源 Agent 授权、detach/interrupt 作用域和禁止重放策略保持原有语义。CLI/MCP 没有新增管理员清理工具。

## 远程脚本导出故障

导出失败提示区分 `selection`（选择保存路径）、`preparation`（准备预览）、`confirmation`（确认写入）。IPC 返回 `code`、`stage`、`path` 和固定中文 `error`；路径仅为可安全显示的本机绝对路径，确认阶段取已绑定的预览路径。异常消息、内部配置和令牌不会出现在诊断中。未分类异常显示 `EXPORT_UNEXPECTED`。取消文件选择直接返回，不准备或写入文件。

常见诊断码：`EXPORT_TARGET_EXISTS`（目标已存在）、`EXPORT_EXTENSION` / `EXPORT_PATH_INVALID` / `EXPORT_PARENT_MISSING`（路径）、`EXPORT_PROTECTED_PATH`（程序包或运行目录）、`EXPORT_REPARSE_POINT` / `EXPORT_ACCESS_DENIED` / `EXPORT_IO_UNAVAILABLE`（路径安全、权限或文件访问）、`EXPORT_SOURCE_MISSING` / `EXPORT_SOURCE_INVALID`（程序包）、`EXPORT_CONFIG_INVALID` / `EXPORT_PAIRING_MISMATCH`（本机配对）、`EXPORT_PROFILE_INVALID` / `EXPORT_SNAPSHOT_CHANGED`（配置或内容已变化）、`EXPORT_CONFIRMATION_INVALID`（确认失效）、`EXPORT_UI_THREAD` / `EXPORT_UI_UNAVAILABLE`（选择器）、`EXPORT_CAPABILITY_UNAVAILABLE` / `EXPORT_CONTEXT_CHANGED` / `EXPORT_REQUEST_REJECTED`（能力与上下文）、`EXPORT_LEGACY_ACTIVE`（旧窗口模式隧道仍运行）。请保留阶段和诊断码；提供所选路径前自行判断是否需要隐去私人目录名。

导出不自动重试、不覆盖目标。确认先消耗票据，再核对最终路径、ACL、配对、配置及程序包内容快照；失败后需重新预览。确认阶段的文件访问错误需先检查目标文件是否生成。阶段和诊断码用于定位原因，合成测试不能证明真实保存框或 Xshell 已验收。

## 日志与输出故障

日志要求见[日志采集参考](log-capture.md)。终端宽度不影响捕获；脚本更新需重新生成或导出并手动运行，不能通过改名启用新采集器。

- 提示已有用户日志：由用户自行决定何时停止；agent 不停止或覆盖它。
- 查看失败阶段：`NoSend` 表示未调用命令 Send；`SendAttempted` 表示已尝试发送，即使调用抛错也不能排除部分发送。StartLog 后路径或 Logging 不匹配、绑定或共享失败时不会发送；实际路径及 Logging 未能验证时，用户需核查并手动停止日志。0.8.0 曾因预创建文件触发 `capture(2).log`；新流程不预创建，不接受编号路径。原生假写入器不能证明真实 Xshell 的共享模式，新流程仍需非生产验收。
- 无实时输出：日志可能尚未刷新；状态/心跳仍更新。不要据此重复提交命令。
- `deadline exceeded (timeout_ms=..., elapsed_ms=...)` 表示等待超过任务时限；`local clock moved backwards` 表示检测到本机时钟回拨。旧脚本的 `deadline or clock change` 无法区分这两种原因。若 actual/expected 日志路径一致且 Logging=true，不应据此判断日志路径错配。超时本身不能证明分页器是根因。
- 新导出脚本在任务子进程设置 `PAGER=cat`、`SYSTEMD_PAGER=cat`、`GIT_PAGER=cat` 等非分页环境，不修改交互终端的外层环境。巡检命令仍显式使用 `--no-pager` 和有界输出；直接调用 more/less 等交互程序不受此保证。脚本不会自动发送翻页键或退出键。
- 编码错误、控制字符、incomplete frame：核对日志编码和文本模式，关闭时间戳和 ANSI；无 BOM UTF-16、GBK、GB18030 需在来源中显式选择并重新导出。保留日志并核查原任务，不做替换字符或屏幕抓取。
- replaced、reparse、truncated、size limit、helper exited：读取已停止；核对错误中的本任务私有路径、磁盘和本地防护。helper 15 秒空闲/2 小时总时限会退出，失败不会自动恢复。

命令派发后 unknown 表示结果不能确认，远端命令可能仍在运行；Bridge 阻断该接入并取消队列，agent 停止。不表示宿主机 Bridge 服务退出。先由操作员独立核查原任务及目标状态；不自动重新接入、重提或重放。身份变化和事件传输不明时，部分输出可能无法安全送达。

成功日志自动清理；失败和崩溃保留路径供核查。只在停止对应脚本和日志后手动清理明确的 job/helper 目录，勿批量删除用户其他日志。真实 Xshell 与 VM 验收同本地模拟测试分开报告。

## 进程与连接诊断

工作台右上角“工具 → 进程诊断”可读取本机快照。0.8.7 起，同一运行目录只允许一个工作台，正常关闭（含任务栏右键关闭窗口）先提交操作员停机请求、等待 Bridge 退出，再清理本桌面的 SSH 隧道。Windows Job Object 绑定已核对的 Bridge 进程句柄；结束任务或桌面崩溃时也会结束该 Bridge，不按进程名称批量清理。独立手动启动的 `xshctl serve` 未被桌面绑定前仍是独立服务。

正常关闭时，未派发任务取消，已派发或运行中且未确认结果的任务标记 unknown；撤销活动接入并持久保存后才停机。写盘失败回滚并保持服务；停机响应未知不重复提交。强制结束时依靠下次启动的既有恢复机制撤销接入、保留 unknown，绝不重放。关闭本地进程不证明远端命令已停止。更新交接沿用原有空闲停机接口，不重复停机。

MCP 默认通过 `/mcp` 的无状态 Streamable HTTP 复用同一 Bridge；新对话不启动常驻 xshctl，也不保留空闲 MCP 会话。普通 CLI 是短时客户端，执行结束即退出。`doctor` / `processes` 的本机 PID、父进程及角色诊断仍为只读，角色未知不猜测归属。

旧 stdio 接入仍兼容：父进程退出、stdin 断开或取消时结束；曾连通 Bridge 后连续不可用 30 秒会退出，约每 5 秒探测、单次超时 3 秒。首次尚未连通时继续等待，健康空闲不退出。仅升级程序不会迁移 AI 客户端已加载的旧配置；需要在客户端的 MCP 设置中切换为 HTTP，或使用工作台支持的自动配置适配器，然后完全退出并重新启动客户端。自动配置的适用范围见[AI 接入与 CLI](user-guide.md#ai-接入与-cli)。不要按名称强杀所有 xshctl。

从旧版切换时，先使用旧工作台结束接入、核对任务，再走既有更新交接以停止旧 Bridge。新工作台拒绝绑定其他程序包路径或缺少 `desktop_shutdown` 能力的旧 Bridge；不会冒充已升级或自动强杀旧服务。全局 MCP/Skill 配置仍需操作员确认安装或更新。
