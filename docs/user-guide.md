# 使用指南

[返回总入口](../README.md)

本文按首次使用到日常操作的顺序说明流程。更新、清理和故障处理统一见[维护与排障](maintenance.md)。

## 启动工作台

在解压后的 Windows x64 便携包中运行 `Start.cmd`。它由打包脚本生成，源码仓库不直接提供此启动文件。工作台及日志采集 helper 需要 .NET Framework 4.8。

### 运行要求与 lite 包

公开发行仅提供 lite 包：**不包含 WebView2 Runtime**，需要工作台所在 Windows 机器已安装 Microsoft Edge WebView2 Evergreen Runtime 和 .NET Framework 4.8。包内保留调用 WebView2 所需的 SDK 库和 loader，并非完全不依赖 WebView2。

根据[微软的分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)，Windows 11 预装 Evergreen Runtime，绝大多数 Windows 10 设备也已有，但不能假定所有机器都有。精简镜像、受管或离线设备应实际检查；仅安装 Edge 浏览器不能证明运行时可用。

可在 Windows 已安装应用中查找 **Microsoft Edge WebView2 Runtime**。若找不到或启动提示缺少运行时，由用户从[微软官方下载页](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)安装 Evergreen Runtime；离线环境使用对应架构的 Standalone Installer。本工具不自动下载安装系统运行时。

### 启动与数据目录

默认数据目录为 `%LOCALAPPDATA%\XshellBridge-local`，其中 `runtime` 保存私有配对、任务和输出。启动脚本 `scripts/start-desktop.ps1` 可通过 `-DataRoot` 指定其他数据根目录。同一运行目录只允许一个工作台；已有后台只有通过认证健康检查、程序路径和退出能力核验后才能由工作台接管。打开新包不会自动替换旧后台，跨版本切换请使用[更新交接流程](maintenance.md#程序更新)。

右键关闭工作台窗口会先保存任务状态、停止 Bridge，再退出界面；结束任务或崩溃时，Windows 会清理所属 Bridge。尚未派发的任务取消，派发后未确认的结果保留为 unknown；强制结束时，任务状态由下次启动的恢复流程处理。不自动重放，也不保证远端命令已停止。重新启动后需要在 Xshell 手动重新接入并核对新代次。

## 按使用场景接入

### 堡垒机网页启动 Xshell 客户端

适用于堡垒机支持从网页调用本机 Xshell 的环境。网页入口、认证方式和客户端启动配置由所在环境提供，Bridge 从已经建立的 Xshell 终端开始接入。

1. 用户在堡垒机网页完成登录、所需认证和资产授权，选择目标并启动 Xshell 客户端。
2. 在 Xshell 中完成可能存在的资产菜单、跳转或二次认证，确认已进入最终目标的 POSIX Shell。不要在堡垒机菜单、密码提示或跳转过程中激活 Bridge。
3. 根据 Xshell 所在位置选择[本机接入](#本机-xshell)或[远程接入](#远程-xshell)，在对应终端手动运行脚本，再回到工作台核对并激活。
4. 使用一个已授权的低风险查询确认输出及目标，再进行后续任务。原有堡垒机连接与审计由平台管理；Bridge 的命令审批是额外的一层，不能代替平台授权。

堡垒机代理后的 Xshell 地址、会话名或指纹可能只标识代理连接，不能单凭这些字段证明最终资产。应结合网页所选资产和终端内的目标信息核实；同一终端内切换目标前先撤销 Bridge 接入，切换后重新核对并接入。

前提是客户端允许使用 Xshell 官方脚本 API 和所需日志能力。纯浏览器 WebSSH、禁止脚本的客户端环境或仍停留在交互菜单的会话不能按此流程接入。此处描述通用流程，不代表已经验证所有堡垒机产品或配置。

### 通过 SSH 隧道接入远程 Xshell

适用于 Xshell 在远程 Windows 工作机或虚拟机上运行，而操作者希望在本机工作台审批并使用 CLI/MCP 的情况。远程机器上的 Xshell 可以由用户直接登录，也可以由堡垒机网页启动。

| 连接 | 用途与发起方 |
|---|---|
| 本机工作台 → 远程 Windows 的 OpenSSH 服务 | 用户在工作台显式连接，建立 SSH 反向端口转发 |
| 远程 Xshell 接入脚本 → 远程回环端口 → 隧道 → 本机 Bridge | 脚本获取任务、上报状态及输出；远程机器无需运行另一套 Bridge |
| 远程 Xshell → 已登录业务目标 | 复用用户已建立的业务连接，执行审批后的命令 |

1. 准备远程机器的 OpenSSH 服务、可用于转发的账号与密钥，并通过可信渠道核验主机密钥。确认相关网络及回环端口转发条件满足。
2. 在本机工作台创建“远程 Xshell”配置，填写的是 **Xshell 所在 Windows 机器**的 SSH 入口，并显式连接。详细字段见[远程 Xshell](#远程-xshell)。
3. 预览并确认导出脚本，私密传递到远程机器。脚本包含来源凭据，不应放入代码仓库或公开附件。
4. 用户在远程 Xshell 中登录最终目标，在指定终端手动运行脚本；回到本机工作台核对接入代次、指纹和目标，再激活。
5. 从本机 CLI/MCP 提交任务，在工作台审批并查看输出。隧道中断或结果未知时查询原任务并核查目标，不自动重连、重提或重放命令。

SSH 隧道用于连接脚本与 Bridge，不会通过 SSH 启动或遥控 Xshell 界面，也不会替用户登录业务目标。Xshell 的启动、目标选择和脚本运行均由用户操作。

## 接入终端

先由用户在 Xshell 中登录最终目标，再选择下面对应的接入方式。每个终端分别运行脚本并核对身份；名称和分组不能代替目标核验。

### 本机 Xshell

1. 打开“本机 Xshell”，检查完整路径、安装与程序包版本，设置分组和日志编码。
2. 预览并确认生成脚本。仅原始 Local 操作员配对可写入固定受管路径 `local-agent/xshell_agent.js`，它位于原 runtime 的父目录；旧 `runtime/xshell_agent.js` 保留。
3. 复制显示的完整路径，在每个已连接最终目标的终端通过“工具 → 脚本 → 运行”手动运行。
4. 返回工作台核对 session ID、接入代次、指纹及新鲜心跳，确认一次后激活。成功后确认框自动关闭，身份刷新；响应不确定时只刷新，不重复确认。

本机脚本直接访问数字回环 Bridge，不需要 SSH 隧道。检查状态或修改设置不会自动写脚本；更新和文件冲突的处理见[脚本维护](maintenance.md#接入脚本更新)。

### 远程 Xshell

1. 打开“远程 Xshell”，填写配置。连接目标是运行 Xshell 的远程机器 OpenSSH 入口，不是脚本最终操作的业务服务器。
2. 保存后显式点击连接。保存本身不连接；主机密钥须事先通过可信渠道核验。
3. 预览并确认导出 `xshell_agent.js`，私密复制到远程机器。保存框会补全 `.js` 后缀，也可输入完整文件名；已有文件不会被覆盖。
4. 在每个已连接最终目标的终端手动运行脚本，返回工作台核对身份、接入代次和新鲜心跳，再激活。

| 配置 | 含义 |
|---|---|
| 名称、分组 `environment` | 展示和查询用；分组留空时使用名称 |
| `sshHost`、`sshPort`、`user` | 远程机器的 SSH 入口 |
| `keyPath`、`knownHostsPath` | 宿主机上的私钥及已核验 known_hosts 文件绝对路径 |
| `remotePort` | 远程回环监听端口 |

工作台将接入方式固定为 `manual_terminal`。系统 OpenSSH 使用 `-F NUL -N -T -R 127.0.0.1:<远端端口>:127.0.0.1:<本机 Bridge 端口>`，启用 BatchMode、IdentitiesOnly、严格主机密钥检查、ExitOnForwardFailure 和有界 keepalive，不执行远程命令。管理员须核实远端 sshd 和 authorized_keys 允许该回环端口转发。

隧道进程存活不证明转发成功或目标已就绪。远程机器不运行 Bridge 后台或审批桌面。旧窗口模式配置不能直接连接；显式导出新脚本时迁移为逐终端方式，不自动激活或重放。

### 日志设置与操作边界

日志须为可打印文本，关闭时间戳、ANSI 和启动日志时的路径询问。自动编码支持 BOM 和无 BOM UTF-8；无 BOM UTF-16、GBK、GB18030 须在对应来源中选择，再生成或导出脚本。完整机制见[日志采集参考](log-capture.md)。

生成或导出的脚本含来源限定凭据，应私密保存。任务运行时不要手动输入或切换目标。输出为合并的终端转录文本，可能截断，不是独立 stdout/stderr。

## AI 接入与 CLI

CLI 和 MCP 是独立客户端入口，不强制安装或使用特定 AI 产品。可以让具备本机命令执行能力的 AI 工具调用 CLI，或让支持相应传输及认证方式的本机 MCP 客户端连接 Bridge；也可以不用 AI，直接操作 CLI。

### 手动接入 AI 客户端

| 接入方式 | 配置要点 |
|---|---|
| Streamable HTTP MCP（推荐） | 从本机 `client.json` 读取 `endpoint`，在地址后添加 `/mcp`；使用同文件的 client token 配置 Bearer 认证，例如客户端的令牌环境变量或安全凭据设置。端口以实际配置为准 |
| stdio MCP | 程序填写便携包内 `xshctl.exe` 的绝对路径，参数按 `--config`、本机 `client.json` 绝对路径、`mcp` 的顺序配置 |
| CLI | 按[客户端命令参考](../skills/xshctl/references/commands.md)调用 `xshctl` 并处理 JSON 输出，无需安装 MCP 或 Skill |

HTTP MCP 复用工作台的 Bridge，多对话不需要另启常驻 CLI。AI 客户端需要能访问 Bridge 的本机回环地址；云端服务不能直接访问用户电脑的回环地址。不同客户端的配置字段和凭据保存方式不同，应使用其自身支持的配置入口，不将 client token 粘贴进对话或公开仓库。

### 工作台内置的自动配置

工作台“AI 接入”默认展示通用接入信息，本机路径与检测详情默认折叠；路径由当前用户和运行目录生成，并非发行包写死的开发者目录。“客户端自动配置（可选）”当前使用 **Codex 专用适配器**，不是所有 AI 客户端的通用安装器。它可检查、预览 MCP 和 Skill 的安装、更新或卸载；其他 AI 客户端按上面的方式手动配置，不能直接使用此入口替它们写配置。

该适配器由用户确认后执行，保留未知或被用户修改的配置。安装或迁移把 client 配对令牌写入按配置路径区分的当前用户环境变量 `XSHELL_BRIDGE_TOKEN_<标识>`，客户端配置只记录变量名；预览与日志不显示令牌。卸载只删除归属已核对的变量。安装、迁移或令牌变更后，完全退出并重新启动对应客户端以加载用户环境；工作台需要保持打开。

CLI/MCP 使用宿主机 client 配置，不持有管理审批权限。参数与 PowerShell 示例统一见[客户端命令参考](../skills/xshctl/references/commands.md)，选择巡检或文件读取命令见[巡检配方](../skills/xshctl/references/inspection.md)。这些参考与项目 Skill 一起维护，不在本文重复命令表。

## 审批与任务跟踪

明确危险操作会返回 COMMAND_DENIED，不创建待审批任务，也不能通过人工批准覆盖。其余提交成功后保存原任务 ID：默认规则或已有授权匹配时进入队列，否则在工作台等待人工审批；0.8.9 的 v5 包覆盖常用 ls、最大 64 MiB 的 head/tail 字节参数，以及内部命令只读且时限有限的 timeout 包装；不改变危险拒绝。具体命令范围、开关及授权期限统一见[审批规则](approval-policy.md)。

审批中心优先显示待处理命令，默认包折叠在页面底部；自动审批授权页管理规则。核对实际目标和完整命令后，可批准一次或拒绝；符合复用条件的命令还可记住 30 分钟。Python、外部脚本、动态参数及无法完整分析的命令可逐次审批，记住按钮禁用；不能把“无法分析”当作“明确危险”。批量只作用于明确选中且仍显示的最多 20 项。离开审批页会清空选择，新到任务不会自动加入。

审批决定已记录不代表命令完成。工作台就地跟踪本窗口明确处理的原任务，最多保留最近 40 项；完成时显示退出码，并只读获取一次首段输出摘要，最多显示 2000 字符。摘要失败不循环查询，完整输出可按需打开。处理记录只属于当前窗口，连接切换时清除；断线时保留旧状态，新的有效快照才可更新。

原任务身份或内容不匹配时停止跟踪和自动读取。摘要与定时刷新重叠时，等新快照核对身份、内容和退出码后再显示；不匹配或连接失败则丢弃，不重复查询。重复点击不会顺带批准移动到原位置的新卡片。响应未确认时只看原任务状态，不把状态变化当作审批响应成功的证明。

## 查找任务与读取输出

会话行“查看任务”按 session ID 打开任务列表，可单独清除目标范围。各页面保留独立搜索和状态筛选；任务可按原记录的审批来源筛选，顶部统计可打开相应列表。

输出窗口优先展示状态与输出，完整命令和身份可展开。向上滚动或选择文本会暂停跟随，“回到底部”恢复；追加输出保留阅读位置和选区，切换任务忽略旧响应。

结果未知的任务仍可读取已保存的后续分页，直到游标不再前进；读取失败停止自动轮询，可明确重试同一游标。它只读取原记录，不重新执行命令。断线、代次变化或 unknown 的处理见[维护与排障](maintenance.md#日志与输出故障)。

终端表格按新接入持久化的 `created_at` 倒序、相同时间按 ID 升序显示完整日期和时间。心跳、原值注册重试及改名不更新创建时间，新记录不会随心跳跳动。旧记录未保存创建时间时显示“旧记录：以最近心跳代替”，使用完整 `last_seen` 日期排序；两者均未知的记录排最后。旧活动记录的回退值仍可能随心跳更新。排序仅作用于界面副本，CLI/MCP 的 Store 顺序保持不变。
